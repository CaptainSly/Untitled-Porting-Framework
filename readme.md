# Untitled Porting Framework

The Untitled Porting Framework is a porting framework that is meant to help create source ports of console games in Java. 

# Current Status

The current Platform focus is Linux.

The Dependency Stack for UPF is:
- Java 25
- LWJGL 3 using SDL3
- OpenGL 4.6
- OpenAL
- STB
- zstd
- JOML
- Tinylog2
- GSON

The following consoles are currently in active support:
- PS1
    - GTE, Ordering Table, Triangle Batches, PSX Texture and Quad
    - SPU ADPCM, Voices, Reverb, XA ADPCM
    - STR Demux, MDEC, Bitstream Decoder, Movie Player
    - BIN Loader, Disc File System

The following consoles will be supported in the future:
- PS2
- GBA
- GC
- NDS
- Wii (Potentially)
- 3DS (Potentially)
- PSP (Potentially)

# Porting

The main focus of this project is to make creating native source ports of console games easier. You must bring your own games, and always require your users to bring their own assets as well. This isn't a recompilation builder either, you will need to start from a decompilation project and translate the code natively. 

# Customization

The following files should be modified when starting a project in UPF:
- `UPF.java` - Holds constants for window title, game version and engine folder. (The `build.gradle.kts`'s `engineFolder` MUST match the `UPF.ENGINE_FOLDER` constant)
- `Game.java` - Your `EntryPoint` into the Engine.
- `upf-core/build.gradle.kts` - The `engineFolder` variable and `appname` variable should be changed to your projects. 

Remember to exclude your engineFolder from your gitrepo, it will be generated by the code if it doesn't exist. It's located in the working directory.

# Build Instructions

## Requirements
- GraalVM JDK 25
- Linux
- OpenGL 4.6 GPU Support

## Build
Run `./gradlew installDist`
- Output goes into `upf-core/build/install/<appname>/`.
- Start Script is in `bin/<appname>`
- The Engine folder is located next to the executable at `bin/<engineFolder>/`. It contains the `./libs/` directory holding the jar libraries, along with empty `./data/`, `./saves/`, `./config/` and `./mods/` directories for your game data.

## Run
Run `./upf-core/build/install/<appname>/bin/<appname>`
- The VM Commands `--enable-native-access=ALL-UNNAMED` and `--sun-misc-unsafe-memory-access=allow` are passed in for you.
- The Framework looks inside the `<engineFolder>/data/` for the roms when utilizing the PS1 `BinLoader` and `DiscFileSystem`

# FAQ

**Q:** Does this project use AI?

**A:** As an assistant only. I use Claude, but I do not allow Claude to write any code. It can provide pseudo code, but can't write to any files, nor provide compilable Java Code. The framework itself was cobbled together from a few other projects I've been working on. 

**Q:** How do I use it? 

**A:** Fork the project, and then work inside it. Create a package in the `upf-core` project, and keep all your code in there. The `Game.java` class in the `engine` package is the `EntryPoint` into the engine. This is where you'll "run" your game. The `ps1` package makes it easier to write PS1 Source Ports. In the future more console packages will be provided. 

**Q:** Is this an emulator?

**A:** No. The `ps1` package is sort of a hardware emulator, but there isn't a CPU emulator. So you couldn't play ps1 games with UPF. The project is used for creating source ports of console games. You could also use it to write a game as UPF provides Input, Graphics, and Audio. 

**Q:** Does this work on Windows or Mac?

**A:** Windows maybe, the windows natives need to be included in the `build.gradle.kts` for `upf-core`, Mac? No. The Engine is hardcoded for OpenGL 4.6.
